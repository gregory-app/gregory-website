04The month

The month comes to you.

Connect a client’s QuickBooks, Xero or Shopify once. On the pull day you set, Gregory reads one report from each and lines the actuals up against the rows they belong to.

01

One report a month, from each source.

Read straight from the vendor on each client’s pull day, matched to the rows it sums into. No warehouse, no export to chase.

02

Written only under a rule you signed.

Sign a rule once per source and the month applies on its own, through the same gate as every other change. Without one, it waits for you. A file on a desktop always waits.

03

What moved, and one way back.

Each month says what was pulled, what was written, and what still waits. Reverse this month puts the prior numbers back, through the gate.

06Non-negotiables

Enforced in code.

01

Nothing writes without approval.

The only path that changes a workbook runs through changes a person decided. There is no auto-apply, and no way around the gate.

02

The workbook stays yours.

What Gregory leaves in the file uses native features — named ranges, notes, a hidden sheet. No macros, and no add-in required to open it.

03

Excel in, Excel out. Sheets in, Sheets out.

A model lives on one platform for its whole life. Gregory never converts the file into something the client cannot open.

04

No number without a quote.

A proposed value has to point at the source, word for word. What cannot be grounded is flagged as a gap. Approved changes reach the cell as the number you approved.

05

Client data stays where the engagement allows.

Per-engagement flags control cloud processing and AI use. Calls send the minimum text needed, and client values never appear in logs.
